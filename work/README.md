# Тестовые задачи (деки) Монитора-80

Все `*.b6` — пакетные задания для `dispak -p`. Работают на копии тома 2348
из `~/.besm6` (запись идёт только в неё). Логи прогонов лежат рядом с
деками.

## Паспорт задачи шифрования

Шапка задания «скомпилировать программу с GOSTLIB и выполнить»:

```
шифр 419999 зс5^            ; шифр задачи + служебные признаки
лен 40(2348)^               ; том 2348 на ЛУ 40 (октально), только чтение
eeв1а3                      ; карта режимов задачи (как в штатных деках)
*name                       ; начало задачи, заводка каталога
*call yesmemory             ; расширенная память
*perso:402570               ; самодостаточная библиотека: PASCOMPL 15.1 +
                            ;   обвязка + GOSTLIB + ARFALIB (зона 02570)
*stand                      ; брать компилятор из PERSO (модульный режим)
*call *pascal               ; запуск компилятора
program cipher(output);
...текст программы...
*execute                    ; выполнить скомпилированное
*end file
``````
ЕКОНЕЦ
```

Правила:

- `*perso:402570` — единственная строка загрузки: в библиотеке 02570
  есть и компилятор, и GOSTLIB, и runtime (собрана 01.11.26,
  см. `docs/CLEANUP-2026-11-01.md`). Прежние экземпляры компилятора
  (02030, 02100, 02540) и runtime 02000 из дек удалены.

- `-wr` в карте `лен` — только в задачах записи (сборка/перенос библиотек).
- Для записи результата вместо `*execute` ставится `*to perso:40ZZZZ`.
- Строки деки — не длиннее 72 символов: ввод обрезается по 72-й колонке,
  хвост `external`-объявлений теряется и компилятор сыплет ложные
  ошибки (84/12/52) в случайных местах.

`golden_1task_h.b6` исправлена опечатка исходника: `infwrd:=ddisk;`
вместо `odisk:=infwrd;`. Семантика Е50 0116 (освобождение снимает
только захват, привязка тома к каналу сохраняется) разобрана по
исходникам ОС в `docs/GOLDEN-DIALOG.md`.

## Порядок воспроизведения библиотеки

1. `build_gostlib.b6` — компиляция исходника и запись в 402540;
2. `ext_gostlib.b6` — извлечение модуля `GOSTLIB` в 402560 (3 зоны);
3. `tgost1_enc.b6`, `tgost1_ctr.b6`, `tgost1_msg.b6` — верификация.

## БД хешей паролей на спецносителе (лента 203, том АРФЫ)

Диалоговая программа `bd_203.b6` (меню 1-5, 0) — создание и редакция БД
«шифр пользователя → хеш пароля» (ГОСТ 34.11-94, 8 слов) на
зашифрованном томе АРФЫ ленты 203, хозяин области — системный
пользователь 419999.

Структура деки (сборка `scripts/build_bd_203.py` из фрагментов):

- шапка: `dis 40(2048-630)` — **код МАРСа** (читается Э70 из PASBDI,
  «настройка на код МАРСа»), `dis 41(2348)` — библиотека 02570,
  `*perso:412570`;
- DTRAN-преамбула МАРСа (`*assem`): ячейки `*bdvect*` (168 слов, с
  трюком `,bss,377b` — старт с адреса 01400), `*erstop*`, `*bdv*`,
  `*bderrn*`, `*bdc*` и области `p/bdsys`, `p/bdtab`, `p/bdbuf` —
  **без них PASBDI из библиотеки работает с мусорными указателями и
  падает «ЗАТЕРТО СПО»**;
- механизм golden (ГОСТ + Passgen/HashMessage) + переменные Э63/МАРСа
  (`curk: mw` — ключ итератора как слово, `pad16`, `cifr2`);
- процедуры Э63/Э50 (`bd_procs.txt`): `grabvolume`/`releasevolume` —
  **монопольный захват/освобождение спецносителя Э50 0157/0116**
  (номер тома в ДДК: 203 → `1003B`);
- главный диалог (`bd_main.txt`);
- завершение: `*main start` (вход через DTRAN `start` → `uj main`).

Прогон (том 203 ищется по BESM6_PATH и захватывается Э50 0157):

```sh
python3 work/run_bd_pty.py work/bd_203.b6 create   # 1,3999,2×2 юзера,5,0
python3 work/run_bd_pty.py work/bd_203.b6 verify    # 5,3×2,0 - новый сеанс
```

## Запись диалоговой программы в библиотеку и вызов по имени

`bd_203.b6` компилирует программу и выполняет её в одном задании
(как golden). Чтобы не транслировать исходник при каждом обращении,
программа записана в библиотеку 02570 тома 2348 и вызывается по имени.

- `build_bd203_save.py` собирает из чистой `bd_203.b6` деку `bd203_save.b6`:
  `dis 41(2348-wr)`, программа переименована в `bd203` (имя модуля
  каталога, не длиннее 8 букв), DTRAN-обвязка `start:` ссылается на
  `bd203`, хвост `*to perso:412570` вместо `*execute`. Прогон записал
  модуль и напечатал `ДЛИНА LIBRARY 042 ЗОН` (эталон `bd203_save.log`).
- Паспорт (шапка) модуля — запись в каталоге зоны 02570: `ВД203`
  (модуль, сл.0002), точка входа `ПРОГРАМ`, модуль `СТАРТ` (DTRAN:
  ячейки `*bdvect*` и `,uj,bd203`). Проверка: `persocat.py 2348 02570`.
- `bd203_run.b6` — дека вызова без трансляции (13 строк):

```
шифр 419999 зс5^
dis 40(2048-630)^      ; код МАРСа для PASBDI
dis 41(2348)^          ; библиотека 02570 (ВД203)
ОЗУ 32^ АЦПУ 140^ ТРА 37^ ТЕЛЕ^
eeв1а3
*name
*call yesmemory
*perso:412570
*no list
*call start            ; СТАРТ -> ВД203: монопольный захват и диалог
*end file
```

Проверено на чистой ленте `203.clean`: сеанс 1 (`create` — захват
Э50 0157 КОД=0, создание области, пароль, каталог МАРСа, HASHPW,
два пользователя) и сеанс 2 (`verify` — те же хеши из БД, Э50 0116);
эталоны `bd203_run_create.log`, `bd203_run_verify.log`.

Особенность МАРС-6 на ленте: последнее слово значения искажается
младшими разрядами при записи, поэтому 8-е слово хеша дублируется
записью-спутником (ключ «X…», 8-е слово первым). `newd` печатает
безвредную диагностику «03 DATA BASE ERROR». Итератор BEGIN NEXT на
ленте зацикливается — пункт «список всех записей» отключён.

Том после создания: метка «ARFA 203», признак архивного тома
(невидим в СЕРПе, закрыт для Э70), каталог в 5 зонах, область
ПАРОЛИ (3 зоны) с каталогом МАРСа и файлом HASHPW.

## Пользовательские программы раздела (записаны в библиотеку 2348)

По образцу тестов `t1_hash`/`t2_wr203`/`t3_rd203` собраны и записаны
в библиотеку 02570 тома 2348 три пользовательские программы работы с
зашифрованным разделом ТЕСТ/419999 ленты 203 (сборка
`build_user203.py`, памятка пользователя — `docs/ПОЛЬЗОВАТЕЛЬ-203.md`):

| Программа | Вход (`*call`) | Что делает |
|-----------|----------------|------------|
| ПАР203 | `parol` | задание хеш-пароля (ГОСТ 34.11-94): секретный ввод дважды, печать 8 слов хеша |
| ЗАП203 | `zapis` | захват 203 (Э50 0157), при отсутствии — создание раздела (Э63 01) и шифра доступа (Э63 03), шифрование сообщения хеш-паролем (ГОСТ 28147-89, гаммирование) и запись в зону 0 раздела, контрольное чтение, освобождение (Э50 0116) |
| ПРО203 | `prosm` | захват 203, чтение шифртекста из раздела, расшифровка хеш-паролем, печать сообщения, освобождение |

- Деки записи `<имя>_save.b6` (`dis 41(2348-wr)`, `*perso:412570`,
  DTRAN-обвязка `<вход> → uj <программа>`, хвост `*to perso:412570`)
  запускаются под pty (`run_save_pty.py` — автопереводы строк на
  приглашения `WНАТ=`). Имена входов (ПАРОЛ/ЗАПИС/ПРОСМ) и программ
  (ПАР203/ЗАП203/ПРО203) различны, чтобы не столкнуться в каталоге
  между собой и с СТАРТ/ВД203; после записей каталог содержит
  `РАR203/РАRОL`, `ZАР203/ZАРIS`, `РRО203/РRОSМ`, СТАРТ/ВД203 целы,
  библиотека 065 зон.
- Деки вызова `<имя>_run.b6` (15 строк, `лен 40(2348)`,
  `*perso:402570`, `*call <вход>`) — без трансляции, прогон секундный.
- Диалог: `Passgen` спрашивает пароль дважды (от 8 до 80 символов,
  внутренний контроль совпадения), `Passver` — один раз (секретный
  ввод). Ответы прогонов заданы в `run_user203.py`
  (`par`: пароль×2; `zap`: шифр доступа, пароль×2, сообщение;
  `pro`/`proneg`: пароль).
- Прогоны 04.11.26 (свежий том `203.clean` → `tstage/203`):
  ПАР203 — хеш совпал с эталоном t1; ЗАП203 — раздел создан, шифр
  3999, сообщение `user-arfa-203` записано (16 слов, контроль верен);
  ПРО203 — расшифровано `USER-ARFA-203`; ПРО203 с неверным паролем —
  печатает нечитаемый мусор и подсказку (эталоны `par203_run.log`,
  `zap203_run.log`, `pro203_run.log`, `proneg_run.log`).
- Повторная запись после правок исходников (`u_par_main.txt`,
  `u_zap_main.txt`, `u_pro_main.txt`):
  `python3 work/build_user203.py && python3 work/run_save_pty.py
  work/<имя>_save.b6`; проверка цикла — `python3 work/run_user203.py`.
