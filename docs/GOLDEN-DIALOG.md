# Диалоговый golden: полный прогон под pty

Дата: 31.10.26. Проверялась диалоговая программа шифрования
`golden/gost_08.05.2025_new.pas` (система ГОСТ-БЭСМ от 30.04.2025)
в пакетном `dispak` с реализованным экстракодом Е50 0157.

## Итог

Golden проходит весь диалог в одном задании: выбор спецносителя,
создание пароля, шифрование и расшифрование `HELLO`, выход. Задача
завершается штатно (`КОНЕЦ ЗАДАЧИ`, `*74`), без `ОШ.В ИНФ.СЛ.ЭКСТ`.
Лог проверенного прогона — `work/golden_pty.log`, ответов 18/18.

## Дека

`work/golden_1task_h.b6` — паспорт, `ТЕЛЕ^`, исходник golden целиком,
`*perso:402000,cont` (runtime) и `*execute`. Компиляция: 3529 строк,
каталог программы 01000, runtime `LIВRАRУ ОТ 18.03.25`.

В исходном golden есть опечатка в ветке `engmode=1` (строка 2577):

```
odisk:=infwrd;
infwrd:=infwrd;
BESM(500157B);
```

Нужно `infwrd:=ddisk;` — иначе в Е50 0157 передаётся не номер тома,
а нулевое/мусорное информационное слово. В тестовой деке это место
исправлено (`work/golden_1task_h.b6`, строка 2575); сам
`golden/gost_08.05.2025_new.pas` не менялся.

## Е50 0157 в dispak

Реализация — `dispak/dispak/extra.c`, функция `e50_157()`:

- вход: младшие 16 разрядов `acc.r` — номер тома в двоично-десятичном
  виде (для golden `2061` это `0o20141`);
- выход: `acc.l = acc.r = 0` — том захвачен, `acc.r = 1` — ошибка
  (неверный BCD, номер вне 1–4095, нет образа или свободного канала);
- если том уже привязан к каналу 030–067, захват просто отмечается;
- иначе том привязывается к первому свободному каналу (в golden это
  031: 030 занят томом 2048, 040 — томом 2348), режим чтение/запись;
- захват относится к набору данных и держится до конца задачи: отказ
  от МЛ/МД (Э72 с кодом 020) его не снимает, а явное освобождение —
  Е50 0116 с тем же BCD-номером — снимает (том при этом остаётся
  привязан к каналу).

Пакетный диспак однопользовательский, конкурирующих задач нет, поэтому
код ответа — всегда 0 при существующем томе.

### Е50 0116 по исходникам ОС

Метка `Э116` в `re-dispak/ekst.be` — это обработчик **0117**
(сохранение слова на системном диске), а не 0116. Настоящая
диспетчеризация видна в `re-dispak/text/ekvvod.be:152-156`
(и в исходном листинге `re-dispak/text/ekvvod_bak.be:323-330`):

```
115 → ПА → Э115  (ENQ)
116 → П1 → Э115  (DEQ, М17=1)
117 → Э116 в модуле ЭКСТ
```

Ветка DEQ (`ОСВ`, `text/ekvvod.be:769-800`) сверяет запрошенный
том с полем `ИЗАХВ(М3)` (запись о захвате в ИПЗ задачи); при
несовпадении — `ПЕ КОНЕЦ1` (незахваченный НД игнорируется), при
совпадении сбрасывает `Е27П21` в `ИЗАХВ(М3)` и бит устройства в
`ЕNQМДС(М16)`, при необходимости освобождает КМД и будит
ожидающие задачи. `ТЗНМД`, таблицу каналов, `УКАЗД` и процедуры
закрытия файла DEQ не трогает.

Отсюда поведение `e50_116()`: снимается только монопольное
владение (`e50_157_locked[u] = 0`), а привязка тома к каналу
(`disks[u].diskno`) сохраняется — открытый файл продолжает
работать. Это же говорит руководство (5.3.23): «отказ от
монопольного владения… для незахваченного НД игнорируется».

## Диалог и ответы pty-раннера

`work/run_golden_pty.py` запускает `dispak -p` на псевдотерминале и
отвечает на приглашения `PASRED` (одиночный `-` в начале строки).
Последовательность из 18 ответов:

| № | Ответ | Что это |
|---|-------|---------|
| 1 | `2061` | номер спецносителя (2048 и 2063 golden отвергает) |
| 2 | `1` | режим: чтение |
| 3 | `100` | начальная зона |
| 4 | `10` | длина массива в зонах |
| 5 | `\x7f` | ETX: закончить ввод параметров носителя |
| 6 | `1` | меню: создать новый пароль |
| 7 | `testpass123` | пароль |
| 8 | `testpass123` | пароль ещё раз |
| 9 | `1` | тип работы: шифрование |
| 10 | `1` | источник: терминал |
| 11 | `HELLO` | строка сообщения |
| 12 | `!!кнц` | конец сообщения |
| 13 | `2061` | носитель для записи |
| 14 | `0` | режим: запись |
| 15 | `100` | начальная зона записи |
| 16 | `10` | длина массива записи |
| 17 | `\x7f` | ETX: закончить ввод параметров носителя |
| 18 | `2` | выход |

ETX (`0x7f`) обязателен после каждого блока параметров носителя: без
него golden снова показывает приглашение длины массива. При шифровании
golden не запрашивает читающий носитель — только носитель записи.

Раннер делает рабочую копию образа `2061` во временном каталоге, чтобы
не писать в исходный носитель.

```
КОД ОТВ. = 0
N НАПР 31
N ПОДКЛ. НМЛ/МД 2061
тип носителя: ЕС-5061 (29 МБ)
...
1 - создать новый пароль, 2 - считать пароль
...
Хэш сумма пароля (численное представление): 8 слов
...
выбранный вид работы - шифрование
...
в файл были записаны следующие строки: HELLO
...
параметры носителя для записи: канал 32, том 2061
...
зашифрованный текст (числовое представление): 7 чисел
расшифрованный текст: HELLO
...

```

Финальный `E70` при закрытии задачи пишет буфер `keyf` (канал 031,
зона 0100). Golden перед этим вызывает `otkdrv(31)` — Э72 020 «отказ
от МЛ», — но захват по 0157 не освобождается, поэтому запись проходит
без ошибки.

## Как повторить

```bash
cd ~/Yandex.Disk/besm-crypto
export BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6:$HOME/Yandex.Disk/simh/BESM6/MD/EC5061"
export PATH="$HOME/Yandex.Disk/dispak/build/dispak:$PATH"
python3 work/run_golden_pty.py work/golden_1task_h.b6 > work/golden_pty.log
```

Для сборки эмулятора с Е50 0157:

```bash
cd ~/Yandex.Disk/dispak/build && make -j$(nproc)
```

## Замечания

- Номера `2048` и `2063` golden сам отвергает как зарезервированные.
- `ТЕЛЕ^` в паспорте обязателен: без него `PASRED` не читает терминал.
- `*perso:402000,cont` перед `*execute` обязателен: без runtime
  программа не получает `PASRED` и файловые операции.

## Обновление 02.11.26: диалог от одной библиотеки 02570

Открытый пункт «не компонуется модуль P/LV штатного runtime» закрыт.
Причина была в самом модуле pasred библиотеки 02570 (унаследован из
Паскаль-системы 02030): он был собран из изменённого исходника —
с непустой главной программой и без ссылки на P/LV («вход в главную
программу», генерируется переключателем s5). Из-за этого P/LV не
компоновался, подготовка ввода не выполнялась, и golden не узнавал
конец сообщения «!!кнц» (буква н приходила кодом 'I'=73 вместо
'H'=72 и не совпадала с литералом программы).

Pasred перезаписан в 02570 декой `dispak/tests/arfalib/pasred-rec.b6`
из исходника `pasred.pas` проекта pascal-re (с единственной правкой,
предписанной комментарием в самом исходнике: `110: ch := ord('H')`).
Записанный модуль NOPROGA побайтово совпадает с эталонным NOPROGRA
runtime-библиотеки 02000 (зоны 02014+, образ 0o230 слов). Дека
теперь грузит только `*perso:402570` (без 402000,cont).

Проверка: `work/run_golden_pty.py work/golden_1task_h.b6` — 18/18
ответов, шифрование и расшифрование HELLO, штатное завершение
`КОНЕЦ ЗАДАЧИ`; эталон — `work/golden_pty_2570.log`. Полный прогон
тестов ДИСПАК — 51/51.

Спецноситель 2061 (образ EC-5061 из каталога simh) в новой среде
отсутствовал и восстановлен как копия тома 2348: паспорт зоны 0
сообщает тип EC-5061 (29 МБ, 7630 зон), признак архивного тома не
установлен, массивы golden пишутся в зоны 0100+ рабочей копии
(раннер копирует носитель во временный каталог). Файл: `work/2061`.
