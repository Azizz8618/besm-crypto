# Спецноситель 203: БД хешей паролей на томе АРФЫ

Дата: 04.11.26. Инструкция пользователя и описание устройства
спецносителя — ленты 203 (том архива АРФА ОС ДИСПАК).

## Что такое носитель 203

Лента 203 — **спецноситель**: зашифрованный том архива АРФА,
созданный системным пользователем (шифр **419999**). На томе:

| Элемент | Что это |
|---------|---------|
| метка тома | «ARFA 203», признак архивного тома (том невидим в СЕРПе и закрыт для прямого обмена Э70) |
| каталог АРФА | 5 зон, записи во всех копиях |
| область `ПАРОЛИ/419999` | 3 зоны, хозяин 419999, пароль области задаётся при создании (1–4095) |
| зона 0 области | каталог МАРСа (система баз данных МАРС-6) |
| зоны 1–2 | файл данных `HASHPW` — собственно БД |

Таблица БД `HASHPW`: колонки «шифр пользователя → хеш пароля».
Хеш — ГОСТ 34.11-94 (HashMessage), 8 слов по 32 разряда. Пароли
хранятся только в виде хешей; при добавлении пользователя пароль
запрашивается дважды (подтверждение), печатается хеш и только он
попадает в БД.

## Диалоговая программа

Работа со спецносителем — диалоговая программа **bd203**
(по образцу golden): монопольный захват тома, меню, освобождение.
Программа скомпилирована и записана в самодостаточную библиотеку
**02570** тома 2348 (персональная библиотека ДИСПАКа), поэтому
вызывается по имени без трансляции.

Паспорт (шапка) модуля — записи в каталоге зоны 02570 тома 2348:

- `ВД203` — модуль программы (сл.0002 каталога; имя не длиннее
  8 букв, как у PASCOMPL/ARFALIB);
- `ПРОГРАМ` — точка входа программы;
- `СТАРТ` — DTRAN-обвязка: рабочие ячейки МАРСа (`*bdvect*`,
  `p/bdsys`, `p/bdtab`, `p/bdbuf`) и переход `,uj,bd203`.

Просмотр каталога:

```sh
python3 scripts/persocat.py work/2348 02570
```

## Как вызвать программу

Дека вызова — `work/bd203_run.b6` (13 строк, без трансляции):

```
шифр 419999 зс5^
dis 40(2048-630)^      ; код МАРСа (читается PASBDI по Э70)
dis 41(2348)^          ; том 2348: библиотека 02570 с программой
ОЗУ 32^
АЦПУ 140^
ТРА 37^
ТЕЛЕ^                  ; обязательно: без ТЕЛЕ PASRED не читает терминал
eeв1а3
*name
*call yesmemory
*perso:412570          ; библиотека: компилятор+runtime+GOSTLIB+МАРС+bd203
*no list
*call start            ; вызов записанной программы по имени
*end file
```

Запуск под эмулятором (том 203 ищется по BESM6_PATH):

```sh
cd besm-crypto
export BESM6_PATH=$PWD/work:/path/to/dispak/build/dispak
export PATH=/path/to/dispak/build/dispak:$PATH
python3 work/run_bd_pty.py work/bd203_run.b6 ответы.txt
```

Альтернатива без pty — подать деку пакетно (`dispak -p`) и отвечать
на приглашения терминала (`-` в начале строки) вручную. Если нужно
перетранслировать программу из исходника (после правок), подаётся
полная дека `work/bd_203.b6`: шапка + DTRAN-преамбула + исходник +
`*main start` + `*execute` (как golden). Перезапись модуля в
библиотеку — дека `work/bd203_save.b6` (`*to perso:412570`,
том 2348 монтируется `-wr`).

## Порядок работы пользователя

1. **Подключить носители.** В паспорте задачи: `dis 40(2048-630)`
   (код МАРСа), `dis 41(2348)` (библиотека). Лента 203 не
   монтируется строкой паспорта: программа сама захватывает том
   экстракодом **Э50 0157** по номеру тома (203 → BCD `1003B`),
   монитор привязывает его к свободному каналу (030–067).
2. **Вызвать программу** `*call start` после `*perso:412570`.
   Программа печатает шапку и код захвата:

```
БД ХЕШЕЙ ПАРОЛЕЙ - ТОМ АРФЫ, ЛЕНТА 203 (419999)
МОНОПОЛЬНЫЙ ЗАХВАТ ТОМА 203 (Э50 0157): КОД= 0
```

   Код 0 — том захвачен в монопольное владение текущей задачей.
   Ненулевой код (том отсутствует/ошибка BCD) — программа печатает
   «ТОМ 203 НЕ ЗАХВАЧЕН» и заканчивается.

3. **Работать по меню:**

| Команда | Действие |
|---------|----------|
| `1` | создать область и базу данных (первый запуск на чистом томе): область `ПАРОЛИ` на 3 зоны, шифр доступа 1–4095 (пароль области), каталог МАРСа, файл `HASHPW` |
| `2` | добавить/заменить пользователя: шифр (6 цифр), пароль дважды — в БД пишется хеш (8 слов) |
| `3` | показать хеш пользователя по шифру |
| `4` | удалить пользователя |
| `5` | сведения об области: хозяин, число зон, права по паролю |
| `0` | конец работы — том освобождается (**Э50 0116**) |

4. **Завершение.** По `0` (или при ошибке захвата/области) программа
   освобождает том и печатает «ТОМ 203 ОСВОБОЖДЕН (Э50 0116)».
   Захват держится всё время диалога: отказ от МЛ/МД (Э72 020) его
   не снимает, поэтому все записи БД идут под монопольным владением.

Пример сеанса создания на чистом томе — `work/bd203_run_create.log`,
чтение во втором сеансе — `work/bd203_run_verify.log` (хеши
совпадают: БД сохраняется на ленте между задачами).

## Замечания по реализации

- Экстракод Э50 0157 принимает номер тома BCD в младших 16 разрядах
  acc.r, ответ кладёт в acc (0 — захвачено); Э50 0116 — освобождение
  (снимает только владение, привязка канала сохраняется). Семантика
  разобрана в `docs/GOLDEN-DIALOG.md`.
- Область заказывается на томе через Э63 12 («дозаказ», шкала ЛУ
  030–038, имя по-новому `ПАРОЛИ/419999`); логический номер тома
  возвращается на СМ и подставляется в дескрипторы МАРСа
  (`len<<18 | lun<<12 | zone`).
- Особенность МАРС-6 на ленте: последнее слово значения искажается
  при записи — 8-е слово хеша дублируется записью-спутником (ключ
  «X…», 8-е слово первым); при чтении слово восстанавливается из
  спутника. `newd` печатает безвредную «03 DATA BASE ERROR».
- Итератор BEGIN/NEXT МАРСа на ленте зацикливается, поэтому пункта
  «список всех записей» в меню нет — хеш смотрится по шифру (п.3).
- Разметка чистого тома: `besmtool arfa-format 203 --label=203`
  (каталог пуст, признак архивного тома установлен). Эталон чистого
  тома — `work/203.clean`; том с созданной БД — `work/203`.
