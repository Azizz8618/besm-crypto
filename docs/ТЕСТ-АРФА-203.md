# Тесты цикла: хеш-пароль → раздел АРФЫ → чтение и расшифровка

Дата: 04.11.26. Три программы на Паскале (БЭСМ-6, pascal-re) для
проверки полного цикла работы со спецносителем 203 — томом архива
АРФЫ ОС ДИСПАК:

1. **t1_hash** — цикл создания хеш-пароля: пароль (секретный ввод,
   двойной) → хеш ГОСТ 34.11-94 (8 слов). Проверяется
   воспроизводимость (тот же пароль → тот же хеш) и чувствительность
   (другой пароль → другой хеш).
2. **t2_wr203** — создание зашифрованного раздела АРФЫ: монопольный
   захват тома (Э50 0157), создание области `ТЕСТ/419999` на 2 зоны
   (Э63 01), пароль области (Э63 03), дозаказ на лог.номер (Э63 12),
   запись шифртекста в зону 0 области. Ключ шифрования ГОСТ
   28147-89 — хеш-пароль из п.1.
3. **t3_rd203** — чтение из раздела и расшифровка хеш-паролем:
   захват тома, дозаказ области, чтение шифртекста из зоны 0,
   повторный ввод пароля → хеш → ключ, расшифровка (гаммирование со
   счётчиком), сверка с контрольным сообщением из t2. Отдельный
   негативный прогон с неверным паролем должен дать FAIL.

Тесты 2 и 3 — разные задачи (разные запуски dispak): состояние
(каталог АРФЫ + шифртекст в зоне области) живёт на ленте 203 между
задачами. Тест 1 ленту не использует.

## Схема цикла

```
        t1 (без ленты)              t2 (задача 1)               t3 (задача 2)
  пароль ──► HashMessage      пароль ──► HashMessage      пароль ──► HashMessage
              (ГОСТ 34.11-94)             │  хеш-пароль               │  хеш-пароль
  хеш ──► печать/сверка                  ▼                          ▼
                                   InitGostCtx               InitGostCtx
                                   (ключ = хеш)              (ключ = хеш)
                                          ▼                          ▲
                              сообщение ─► EncChars               DecChars
                                (CTR-гамма)      │                  │
                                          ▼       │  зона 0 области │
                                   Э63 01/03/12   ▼  на ленте 203   │
                                   шифртекст ──► [XXXX] ──► чтение ─┘
                                                              (Э63 12, Э70)
```

Расшифровка возможна только тем же хеш-паролем: смена пароля меняет
ключ гаммирования и превращает текст в мусор (проверено негативным
прогоном t3neg).

## Устройство программ

Исходники — фрагменты в `work/`:

| Файл | Что содержит |
|------|--------------|
| `t_procs.txt` | процедуры Э63 (e63/e63p, setname, mkarea, setpass, verpass, areainfo, order), grab/release тома (Э50 0157/0116), EncChars/DecChars (гаммирование ГОСТ 28147-89 со счётчиком), печать слов |
| `t1_main.txt`, `t2_main.txt`, `t3_main.txt` | главные модули трёх тестов |
| `build_tests203.py` | сборка дек: механизм (типы/переменные/крипто golden: Passgen/Passver/HashMessage/InitGostCtx/EncryptBlock…) извлекается из проверенной деки `work/bd_203.b6`, к нему пришиваются t_procs и главный модуль |

Готовые деки: `work/t1_hash.b6`, `work/t2_wr203.b6`, `work/t3_rd203.b6`
(по ~2500 строк каждая, шапка как у golden: `лен 40(2348)` +
`*perso:402570`, без МАРС-преамбулы).

Ключевые детали реализации:

- **Область** `ТЕСТ/419999` (ГОСТ-10859 коды в байтах: Т=50, Е=37,
  С=49, /=12) — 2 зоны, размещается АРФОЙ после каталога (зона 0030
  на чистом томе). Имя не совпадает с `ПАРОЛИ/419999` из БД хешей,
  поэтому тесты не затрагивают базу bd203.
- **Спецификация файла** для зоны области: `len<<18 | ЛУ<<12 | зона`
  (как дескрипторы МАРСа): `desc1 := 262144 + unitn*4096` — 1 зона с
  зоны 0. `unitn` — лог.номер из ответа Э63 12 (26₁₀ = ЛУ 032).
  Чтение/запись — `File of Integer` с `reset(f, desc1)` /
  `Rewrite(f)` — обмены Э70 идут через ЛУ заказанной области.
- **Формат зоны 0**: слово 0 — число слов шифртекста с IV (n+1);
  слова 1..n+1 — IV и шифртекст (по слову на символ, как в golden
  EncryptToArray); последнее слово — контрольное повторение длины.
  Файл самоописан, Eof не используется: t3 читает ровно столько
  слов, сколько записал t2.
- **Режим шифрования**: гаммирование со счётчиком — на пару символов
  один блок гаммы `E(IV, счётчик)` (EncryptBlock, 32 раунда Фейстеля,
  S-боксы ГОСТ 34.12-2015), синхропосылка IV — от таймера (CurrTime).
- **Захват тома**: Э50 0157 c BCD-номером 203 (1003В) до всех
  операций, Э50 0116 в конце. Финальный сброс буфера файла на ленту
  происходит при закрытии задачи — после освобождения, но привязка
  канала сохраняется, поэтому запись доходит.

## Как запускать

```sh
cd besm-crypto
python3 work/build_tests203.py        # пересборка дек из фрагментов
python3 work/run_tests203.py          # t1, t2, t3, t3neg по порядку
python3 work/run_tests203.py t2 t3    # выборочно
```

Раннер сам готовит свежий том: `work/203.clean` → `work/tstage/203`
(BESM6_PATH начинается с tstage, поэтому «203» ищется там; том 2348
с библиотекой — из `work/`), запускает `dispak -p` на псевдотерминале
и отвечает на приглашения PASRED (пароль `parol-privat-1`, шифр
области `3999`, сообщение `test-arfa-203`, неверный пароль для
негативного прогона). Логи — `work/t{1,2,3}*.log`.

Проверяемые маркеры: `*** TEST 1/2/3 PASSED ***`, для негативного
прогона — `*** TEST 3 FAILED ***`.

## Отличие от БД bd203 и ограничения

- bd203 хранит в БД **сами хеши** (МАРС-6, записи «шифр → хеш»);
  тесты t1–t3 проверяют **цикл применения** хеш-пароля как ключа
  ГОСТ 28147-89 для раздела АРФЫ — без МАРСа, напрямую зоной.
- Транспортного шифрования АРФЫ эмулятор не выполняет (слова
  каталога реальных томов не расшифрованы): конфиденциальность в
  тесте обеспечивает прикладное гаммирование ГОСТ 28147-89 с ключом
  = хеш-пароль. Пароли областей (Э63 03/05) живут только в памяти
  эмулятора и между задачами не сохраняются — поэтому t3 не
  проверяет пароль области, а только хеш-пароль шифрования.
- IV берётся от таймера эмулятора, поэтому шифртекст при повторных
  прогонах t2 различается — это нормально (гаммирование).
