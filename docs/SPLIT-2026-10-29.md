## Как выполнено разделение

Слитая библиотека 2500 (030 зон, 176 записей каталога) содержала: модуль
GOSTLIB (5 зон) + PASCOMPL 25.10.26 (~14 зон) + обвязку (~9 зон, 124
модуля). Ключевые факты, установленные при разборе:

1. **Вся ГОСТ-часть — один модуль.** GOSTINIT, TESTPWD, TESTHASH,
   TESTEQUA, ROT11, ADD32 — не отдельные модули, а дополнительные точки
   входа GOSTLIB (в каталоге — пары «имя + смещение» со служебным словом,
   у которого старшие 24 бита нулевые).
2. **Служебное слово записи**: младшие 24 бита — инвариант модуля
   (одинаковы у одного модуля в разных библиотеках), старшие 24 бита
   монитор пересчитывает при каждой записи (адрес размещения).
3. **`*LIBLIST` сохраняет дополнительные точки входа** — они переносятся
   вместе с модулем.

   `PASCAL COMPILER 15.1 (28.10.26)`, компиляция и выполнение `77` —

2. **Golden одним прогоном** (`work/golden_1task_h.log`): 3529 LINES,

3. **Новая 2500** (`work/gost_check.log`): `*PERSO:402500` читает

4. Каталог 2030 не содержит ни одного ГОСТ-имени; каталог 2500 содержит
   только GOSTLIB + его точки входа + PROGRAM.

## Замечания

- Файлы `zone2500/0000/*.pas` и `docs/ZONE2500.md` описывают старый
  план «по модулю на зону» — исторические, актуальному состоянию не
  соответствуют (см. `zone2500/LIBRARY.md`).
- Имена модулей в каталогах записаны кодами TEXT: латиница A/B/C
  неотличима от кириллицы А/В/С (гомоглифы) — при составлении карт
  `*TABLE:LIBLIST(...)` достаточно латиницы; исключение — `P/0П`
  (настоящая кириллическая П).
- Модули PASGOST, PASGOST7, P/TXGOST в 2030 — это ввод-вывод кодировки
  ГОСТ-10859 (часть Паскаль-системы), а НЕ шифрование.

## Обновление 30.10.26: GOSTLIB пересобран из исходника (зона 2560)

Исходник библиотеки восстановлен и сохранён в `zone2500/gostlib.pas`
(тела процедур подняты из `golden/gost_08.05.2025_new.pas`). Модуль
пересобран заново и записан в **новую библиотеку 2560** (3 зоны:
каталог 2560-2561, тело 2562).

Сборка и извлечение:

```

...исходник gostlib.pas...
*to perso:402540              ← work/build_gostlib.b6

*to perso:402560              ← work/ext_gostlib.b6; «ДЛИНА LIBRARY 003 ЗОН»

Каталог 2560: `GOSTLIB` (00713) + ADD32, XOR32, ROT11, GOSTINIT,

MSGENCIV, MSGDECIV. Полная таблица смещений — `zone2500/LIBRARY.md`.

```

Модуль размещается после runtime по свободному адресу (02143/03160 в
разных прогонах) — программа остаётся на 01000. Обратный порядок
(после компиляции) вытесняет программу.

Диалектные грабли, выявленные при отладке:

- одна группа `var` на блок (иначе ошибка 84);
- `external`-объявления — после var-группы, до `begin`;
- в параметрах — только именованные типы;
- адрес элемента массива — `ref(x[i])`; `@` допустим лишь в типе (`@Integer`);
- s-box'ы передаются в порядке s8…s1 и заполняются присваиваниями.

Старая копия в 2500 (7 зон) остаётся резервом до приёмки на полном
golden-приложении.
