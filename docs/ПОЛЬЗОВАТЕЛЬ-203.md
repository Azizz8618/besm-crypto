# Работа пользователя со спецносителем — лента 203

Дата: 04.11.26. Программы записаны в библиотеку 02570 тома 2348 и
вызываются по имени, трансляция не нужна.

## Что записано в библиотеке 02570 тома 2348

```
ПАР203 (вход ПАРОЛ)  - задание хеш-пароля пользователя
ЗАП203 (вход ЗАПИС)  - запись сообщения в зашифрованный раздел
ПРО203 (вход ПРОСМ)  - чтение из раздела и расшифровка
ВД203  (вход СТАРТ)  - диалоговая программа БД хешей паролей
                       (обслуживание БД «шифр → хеш»)
```

Каталог: `python3 scripts/persocat.py work/2348 02570`.

Все программы самодостаточны: компилятор, runtime, GOSTLIB и модули
МАРСа входят в библиотеку 02570. Лента 203 строкой паспорта задачи
НЕ монтируется — программа сама захватывает том экстракодом
монопольного захвата **Э50 0157** по номеру тома (203 → BCD `1003B`)
и освобождает **Э50 0116** по окончании работы.

## ПАР203 — задание хеш-пароля (вход `parol`)

Лента не нужна. Программа печатает 8 слов хеша ГОСТ 34.11-94 от
секретного пароля. Диалог:

```
ПАР203: ЗАДАНИЕ ХЕШ-ПАРОЛЯ (ГОСТ 34.11-94)
ПАРОЛЬ ВВОДИТСЯ СЕКРЕТНО, БЕЗ ЭХА, ДВАЖДЫ
ДЛЯ КОНТРОЛЯ. ДЛИНА - ОТ 8 ДО 80 СИМВОЛОВ.
ВВЕДИТЕ ПАРОЛЬ:            <- ввод без эха
ВВЕДИТЕ ПАРОЛЬ СНОВА:      <- повтор для контроля
ПАРОЛИ СОВПАДАЮТ!
ХЕШ-ПАРОЛЬ (8 СЛОВ ПО 32 РАЗРЯДА):
 3217265238 1804854075  891529486 3788429659
 ...
```

Хеш-пароль — это ключ шифрования для ЗАП203/ПРО203: он не хранится
нигде, ключом служит результат хеширования вашего пароля. Один и тот
же пароль всегда даёт один и тот же хеш (эталон: хеш `parol-privat-1`
= `3217265238 1804854075 891529486 3788429659 3538191932 4271339708
3504669347 3456448240`). Чтобы зарегистрировать хеш в БД паролей,
используйте диалоговую программу ВД203 (пункт 2 — добавить
пользователя: шифр + пароль; хеш в БД вычисляется той же процедурой).

## ЗАП203 — запись в зашифрованный раздел (вход `zapis`)

Порядок работы при первом запуске (раздела ещё нет):

1. Монопольный захват тома: `ТОМ 203 ЗАХВАЧЕН МОНОПОЛЬНО (Э50 0157)`.
   Если печатается `ТОМ 203 НЕ ЗАХВАЧЕН (КОД=…)` — том отсутствует
   или занят другой задачей; повторите позже.
2. Создание раздела ТЕСТ/419999 (2 зоны) и установка **шифра
   доступа** (число 1–4095) — его знает администратор раздела;
   в контрольном прогоне шифр `3999`.
3. Ввод **секретного пароля** (дважды, без эха, от 8 до 80 символов).
   Из пароля вычисляется хеш-пароль — ключ ГОСТ 28147-89.
4. Ввод сообщения (до 80 символов). Сообщение шифруется гаммированием
   с синхропосылкой (текущее время) и пишется в зону 0 раздела.
5. Контрольное чтение обратно (`ЗАПИСЬ ПРОВЕРЕНА … - ВЕРНО`),
   освобождение тома (`ТОМ 203 ОСВОБОЖДЕН`).

При повторных запусках (раздел уже создан) пункты 1 и 3–5 — те же,
создание пропускается (`РАЗДЕЛ ТЕСТ УЖЕ ЕСТЬ: ХОЗЯИН=… ЗОН=2`).

## ПРО203 — чтение и расшифровка (вход `prosm`)

1. Захват тома 203 (Э50 0157). Если раздела нет — печатает
   `РАЗДЕЛ ТЕСТ НЕ НАЙДЕН - СНАЧАЛА ЗАПУСТИТЕ ЗАП203`.
2. Чтение шифртекста из зоны 0 раздела (`СЧИТАНО СЛОВ ШИФРТЕКСТА…`).
3. Ввод секретного пароля (один раз, без эха).
4. Печать расшифрованного сообщения. Если текст нечитаем — пароль
   неверен или данные повреждены (проверено: при неверном пароле
   печатается мусор вида `М=6ХIЯ>Z]XF`).
5. Освобождение тома (Э50 0116).

## Полный цикл пользователя

```
ПАР203  - придумать пароль, получить хеш (или сразу к шагу 2)
ЗАП203  - зашифровать и записать сообщение своим паролем
ПРО203  - прочитать и расшифровать тем же паролем
ВД203   - (администратор) БД «шифр пользователя → хеш пароля»
```

Данные на ленте: раздел ТЕСТ/419999 (2 зоны, хозяин 419999), зона 0 —
заголовок (число слов), синхропосылка и шифртекст (слово на символ),
концевое контрольное слово. Ключ нигде не хранится: без пароля
восстановление сообщения невозможно.

## Ограничения и особенности

- Сообщение — до 80 символов за один запуск (зона 0 раздела).
- Пароль — от 8 до 80 символов, регистр значим (кодировка ГОСТ).
- Раздел один и общий: запись ЗАП203 затирает предыдущее сообщение
  (по одной записи в зоне 0). Монопольный захват защищает от
  одновременной записи двумя задачами.
- Имена входов и программ различны (ПАРОЛ≠ПАР203 и т.д.) — вызов
  `*call parol` поднимет именно программу ПАР203; прямой вызов
  `*call par203` не используется.
- Итератор МАРСа на ленте зацикливается, поэтому списки записей БД
  в ВД203 отключены (см. work/README.md).
